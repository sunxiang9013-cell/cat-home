# 编译与烧录

从项目根目录执行以下 PowerShell 命令。环境：Arduino CLI、Arduino-ESP32 **3.3.11**、Node.js。无需额外安装 ESP32Servo。草图文件夹保留 CatCameraControl / CatCameraRemote，与 ino 同名。

## 从源码编译

```powershell
node '.\Web源码\embed-web.mjs'
arduino-cli compile --fqbn 'esp32:esp32:esp32s3:FlashSize=8M,PartitionScheme=default_8MB,PSRAM=opi,CDCOnBoot=cdc,USBMode=hwcdc,UploadSpeed=115200' --warnings all --output-dir "$env:TEMP/cat-home-main-release" '.\主控板源码\CatCameraControl'
arduino-cli compile --fqbn 'esp32:esp32:esp32cam' --warnings all --output-dir "$env:TEMP/cat-home-camera-release" '.\副板源码\CatCameraRemote'
```

编译使用 Arduino 默认缓存目录；不要把 --build-path 指向中文路径，Windows 链接器可能无法生成输出文件。--output-dir 是编译完成后的导出目录。

编译可能另生成 ELF、MAP、合并映像等；下述分段烧录只需要四个 BIN。现存两板固件包含 Wi-Fi 搜索；副板已移除 OTA，使用 ESP32-CAM 默认 huge_app 单应用分区。两板 pair-2 已完成 USB 烧录及出图检查，见 [固件校验](固件校验.md)。重新编译后，只将导出目录的 *.ino.bin、*.ino.bootloader.bin、*.ino.partitions.bin 复制到对应固件目录，保留对应的 boot_app0.bin；不要复制 ELF、MAP 或 merged.bin。更新校验清单。

## 烧录现有固件

先用 arduino-cli board list 核对串口。COM6 / COM15 是此前端口；下列工具路径对应本机已安装版本，安装版本变化时调整。

```powershell
$espTool = Join-Path $env:LOCALAPPDATA 'Arduino15\packages\esp32\tools\esptool_py\5.3.1\esptool.exe'
# 主控 ESP32-S3-CAM
& $espTool --chip esp32s3 --port COM6 --baud 115200 write-flash --flash-mode dio --flash-freq 80m --flash-size 8MB 0x0 '.\主控板固件\CatCameraControl.ino.bootloader.bin' 0x8000 '.\主控板固件\CatCameraControl.ino.partitions.bin' 0xe000 '.\主控板固件\boot_app0.bin' 0x10000 '.\主控板固件\CatCameraControl.ino.bin'
# 副板经典 ESP32-CAM
& $espTool --chip esp32 --port COM15 --baud 115200 write-flash --flash-mode dio --flash-freq 80m --flash-size 4MB 0x1000 '.\副板固件\CatCameraRemote.ino.bootloader.bin' 0x8000 '.\副板固件\CatCameraRemote.ino.partitions.bin' 0xe000 '.\副板固件\boot_app0.bin' 0x10000 '.\副板固件\CatCameraRemote.ino.bin'
```

| 文件 | 主控地址 | 副板地址 |
| --- | --- | --- |
| *.ino.bootloader.bin | 0x0 | 0x1000 |
| *.ino.partitions.bin | 0x8000 | 0x8000 |
| boot_app0.bin | 0xe000 | 0xe000 |
| *.ino.bin | 0x10000 | 0x10000 |

从原双应用分区恢复本版时，必须执行完整四段 USB 烧录：同时更新分区表、boot_app0 和应用，确保启动到 0x10000。不要通过旧的升级网页上传本版，也不要只刷应用。烧录后按 RST 正常启动；如使用 IO0-GND 下载跳线，先断开跳线。后续固件更新均通过 USB。

不可混用两板固件。上述写入范围不覆盖当前分区表的 NVS，正常更新保留 Wi-Fi；不要执行整片擦除。全新板需通过 USB 初始化网络。

## USB 与维护

主控串口 921600，副板 115200，命令以换行结束。status 查询状态。首次配网格式为 wifi <SSID的UTF-8十六进制> <密码的UTF-8十六进制>，开放网络密码字段为 -。十六进制不是加密，不要把凭据写入源码、文档或日志。成功联网后才保存到 NVS。已在线设备优先用网页配网。

两份 wifi_settings.h 内容应一致：主控文件为维护源，修改后同步副板，副板通过 CAT_REMOTE_CAMERA 改变跨源策略。



## 副板分区

使用 Arduino-ESP32 3.3.11 的 ESP32-CAM 默认 huge_app，无自定义 partitions.csv。只有一个 3 MiB 应用分区（0x10000，长度 0x300000）；NVS 保持 0x9000、长度 0x5000。框架默认仍包含 otadata 和 ota_0 分区类型以及 boot_app0 文件，这是启动布局，不表示应用提供无线升级功能。没有备用应用分区，也没有 `/update` 或 `/api/ota` 服务。

## 双板自动发现版本

主控 cat-home-pair-2、副板 cat-camera-remote-pair-2 必须配套更新。两份 device_discovery.h 与 wifi_settings.h 均需保持一致。device_discovery.h 固定配对本产品的两个 MAC；更换板子时更新对应身份并重新编译配套网页 device-network.js。主控注册上限为 32 个 HTTP 路由，副板 12 个；不要恢复旧版路由上限。
