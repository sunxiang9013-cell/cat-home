# 两台设备统一 Wi-Fi 与地址自动发现

当前源码版本：主控 cat-home-pair-2，副板 cat-camera-remote-pair-2。两块板都需要更新；副板仍不支持 OTA。

## 手机操作

打开猫窝主界面，点右上角 Wi-Fi，搜索或输入一个 2.4GHz 网络，填写密码，点击“两台一起连接”。不再提供单独设置某一块板的选项。两台在线且身份确认后才会开始切换；找不到二号板时先恢复两台在同一局域网，不会悄悄只改主控。

手机需要自行连接目标 Wi-Fi。保持原页面打开，页面会寻找主控的新地址；主控找到二号板后，摄像头会自动使用它的新地址。摄像头区域的“重新发现”仅重新查询设备，不要求输入 IP。旧浏览器保存的 cat-home-camera-2 不再作为连接来源。

## 自动发现与边界

两板每 3 秒发送一次局域网 UDP 心跳（42137 端口），按固定的配对 MAC 和角色匹配，不把任意 ESP32 当成本产品的摄像头。15 秒未收到心跳就标为离线；本机 IP、接入点或联网状态变化时立即丢弃旧地址。已发现后同时使用广播和单播保活。广播不携带 Wi-Fi 密码。

主控 `/api/device` 和 `/api/devices` 返回产品、角色、设备身份、当前 IP 及配对板的在线状态和地址。页面每 5 秒查询主控，发现地址变化就终止旧视频并连接新地址。设备身份匹配不是网络攻击防护认证；不要把接口直接暴露到公网。

主界面自己的地址发生变化时：先尝试 cat-home.local，再有限并发地查找上次所在的 /24 网段；只有产品及主控 MAC 匹配才自动跳转。浏览器不能收 UDP 广播，也不能读取手机的新网关。因此 **若新 Wi-Fi 使用不同网段，同时不支持 mDNS，本地网页不能保证自动找到主控**。此时从路由器设备列表打开 cat-home，网页加载后二号地址仍自动发现，无需手填摄像头 IP。设备断电、访客网络隔离、广播被拦截也可能使发现失败。

## 切网确认

两台 bootId、deviceId 都校验通过后发送 prepare；只有两台都确认准备好，才分别发送同一个 requestId 的 commit。准备失败时取消准备，不发送 commit。

commit 回复丢失时先 GET 核对状态：已 queued/connecting/connected 就继续确认；只有确认仍 prepared 才重试同一个 commit。提交可能已送达后不再自动向两台发 cancel。网络切换造成原地址失联时显示等待确认，不冒充成功或把超时等同于失败。最终成功必须满足对应 bootId/requestId、connected=true、SSID 等于目标网络。

两个独立设备在无线故障下不能保证原子切换：一块板接收不到 commit 或无法连接目标网络时仍可能分处两张网络。页面分别显示状态，必要时通过 USB 恢复共同网络。网页不保存密码，串口应急配网保留。

## 搜索与验证

搜索合并两块板看到的 2.4GHz 网络，并标明来源；点击仅填入网络名，提交前不会切网。Wi-Fi 面板打开时暂停当前网页的视频连接，关闭且无切网任务时恢复，减少配网期间的带宽争抢。

离线测试覆盖：两台一起提交、丢回复后读取确认、准备失败不提交、缺板/身份不符不发送密码、地址变化、无手填 IP、手机 320/390px、mDNS 跨网段与原网段地址查找。实机记录见 [固件校验](固件校验.md)。

切换 Allensun 时，一号切换成功，二号同一 requestId 的准备任务超时取消（expired），仍在 2313。已单独恢复二号至 Allensun，两台互相发现并出图。当前主界面最近地址为 http://192.168.0.3/，副板为 .4，地址可能随 DHCP 改变。本次整理没有修改切网协议，不能认为该可靠性问题已修复。

网页设置只改变开发板的网络，不会替手机或电脑切换 Wi-Fi。网页加载失败时，其内置发现逻辑也无法执行；固定场所可在路由器按设备 MAC 设置 DHCP 地址保留。主控 MAC 为 1c:db:d4:75:10:ec，副板为 88:f1:55:67:97:d0。
